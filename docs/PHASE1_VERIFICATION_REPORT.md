## 2. Files Changed and Reason for Each Change

### 1. `app/saas.py`
- **Race-Free Atomic Upvote:** Replaced vulnerable `SELECT` then `INSERT` race condition with atomic `INSERT INTO feature_request_votes (request_id, voter_id) VALUES (%s, %s) ON CONFLICT (request_id, voter_id) DO NOTHING RETURNING 1`.
- **Foreign Key Validation:** Added validation in `submit_feature_request` ensuring `data.org_id` exists in `organizations` before attempting insertion, raising a clean `ValueError` rather than triggering unhandled PostgreSQL `ForeignKeyViolation`.

### 2. `app/main.py`
- **Safe Error Shielding:** Updated `/api/saas/organizations`, `/api/saas/feature-requests`, and `/api/saas/feature-requests/{req_id}/upvote` to catch `ValueError` cleanly (returning 400/404) and mask unexpected database connection errors behind generic HTTP 500 messages, protecting database credentials and schema details.
- **Resumable Reindex Parameter:** Updated `@app.post('/api/documents/rag/reindex')` to accept `only_stale: bool = False`.

### 3. `app/rag.py`
- **Incompatible Vector Space Protection:** In `retrieve()`, added `AND model_name = %s` to the pgvector distance query (`ORDER BY embedding <=> %s`). This ensures query vectors from model $M_1$ are never mathematically compared against document vectors generated by model $M_2$, eliminating corrupted cosine rankings.
- **Multi-Tenant Org Scoping:** Added `org_id` parameter to `retrieve()`: `property_id IN (SELECT property_id FROM properties WHERE org_id = %s)`.
- **Provenance Transparency:** Updated returned chunk dictionaries to return both chunk-level metadata (`embedding_model`, `is_semantic`) and query-level metadata (`query_model`, `query_is_semantic`).
- **Resumable Reindexing & PostgreSQL Compatibility:** Implemented `only_stale: bool = False` in `reindex_all_documents()`. Replaced invalid `SELECT DISTINCT ... ORDER BY` with PostgreSQL-compliant `EXISTS` subqueries. When batching with `limit`, stale documents are prioritized first. Added `remaining_stale_documents` and `reindex_complete` tracking.
- **Precise Diagnostics:** Updated `get_rag_status()` to accurately count `stale_documents_count` and set `reindex_recommended` based on real discrepancy detection against the active model.

### 4. `tests/test_saas_persistence.py`
- Added `test_concurrent_upvotes_and_duplicate_vote_protection`: Verifies 10 concurrent threads with identical `voter_id` yield exactly 1 successful vote and 9 `duplicate_prevented` responses; verifies 10 concurrent threads with distinct `voter_id` accurately increment vote count by 10.
- Added `test_foreign_key_validation_and_cascade`: Verifies submitting for an invalid org raises `ValueError`, and deleting an organization cascades to delete feature requests and votes.
- Added `test_database_initialization_seed_idempotency`: Verifies calling `init_database()` repeatedly preserves existing records without resetting vote counts or duplicating rows.

### 5. `tests/test_semantic_rag.py`
- Added autouse fixture `clean_synthetic_docs` to ensure all synthetic test documents are cleanly deleted after test execution without deleting real project data.
- Added `test_unrelated_query_ranking_discrimination`: Verifies a query for plumbing repair strongly prioritizes the plumbing manual over an unrelated late fee delinquency clause.
- Added `test_tenant_and_organization_isolation`: Verifies multi-tenant isolation where queries under `ORG-APEX` cannot access `ORG-BEACON` documents and vice versa.
- Added `test_nvidia_failure_fallback_and_index_integrity`: Mocks an NVIDIA NIM failure (503 / timeout) and verifies graceful fallback to `deterministic-hash-v1` with `is_semantic=False` and zero database corruption.
- Added `test_incompatible_embedding_models_prevention`: Verifies that querying a deterministic document with a neural model skips invalid vector comparison and safely falls back to PostgreSQL FTS keyword search.

- **Query:** `"financial punishment for overdue payment"` (Zero lexical words match).
- **Result:** Retrieved `DOC-A` with `rrf_score = 0.016393`, `is_semantic: True`, ranking it #1 over distractor maintenance documents.

### Scenario 2: Unrelated Query Discrimination
- **Indexed Documents:** `DOC-DELINQ` (Late fees) vs `DOC-PLUMB` (Water pipe leakage).
- **Query:** `"bathroom water pipe leakage and drain repair"`.
- **Result:** `DOC-PLUMB` ranked #1 with highest RRF score. Late fee document was not falsely prioritized.

### Scenario 3: Organization & Tenant Access Scoping
- **Setup:** Document A indexed under `PROP-001` (`ORG-APEX`), Document B indexed under `PROP-003` (`ORG-BEACON`).
- **Retrieval with `org_id="ORG-APEX"`:** Retrieved Document A. Document B was **100% excluded**.
- **Retrieval with `org_id="ORG-BEACON"`:** Retrieved Document B. Document A was **100% excluded**.
- **Cross-Tenant Attack Attempt:** Querying specifically for Document A's contents under `ORG-BEACON` yielded 0 matches for Document A.

### Scenario 4: Failover Resilience & DB Integrity
- **Setup:** Simulated complete NVIDIA NIM 503 outage / network timeout.
- **Ingestion Result:** Document ingested cleanly using `deterministic-hash-v1` with `is_semantic=False`.
- **Retrieval Result:** Query succeeded using deterministic fallback without exceptions or database index corruption.

### Scenario 5: Incompatible Model Isolation
- **Setup:** Document chunk indexed with `model_name = 'deterministic-hash-v1'`. Query executed with `query_model = 'nvidia/nemotron-3.5-embed-1b'`.
- **Result:** pgvector cosine distance was safely skipped (`sem_where` filter), preventing invalid distance calculations across distinct vector spaces. Full-Text Search (FTS) correctly identified the chunk lexically and RRF ranked it cleanly.

## 6. Remaining Risks & Recommended Next Steps

### Operational Insights
1. **Embedding API Latency:** Calling NVIDIA NIM sequentially for thousands of passages during a cold-start full reindex takes ~2–3 minutes due to network round-trips. The new `only_stale=True` implementation eliminates this overhead during normal operations by indexing only new or modified documents.
2. **PostgreSQL pgvector Dimension Limit:** pgvector 0.8.7 enforces an upper limit of 2,000 dimensions for HNSW indexes. Preserving the 384-dimensional MRL configuration ensures high semantic retrieval precision while remaining well within index constraints and maintaining compatibility with existing database columns.
